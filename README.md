# 🌀 Spice — ระบบตั้งคำถามแบบก้นหอย

*A self-expanding epistemic system: it asks, answers, finds what its answer
cannot explain, discovers its own blind spots, and builds new instruments
to ask past them.*

```
K_n ──▶ Q_n ──▶ E_n ──▶ A_n ──▶ C_n ──▶ M_{n+1} ──▶ Q_{n+1} ──▶ …
ความรู้  คำถาม  สืบค้น  คำตอบ  ขัดแย้ง  แบบจำลอง   คำถามรุ่นถัดไป
```

ระบบนี้ **ไม่ได้** ตั้งเป้าเป็น "ระบบที่ไม่มีขอบเขต" — อันนั้นเป็นไปไม่ได้
หน่วยความจำ เวลา พลังงาน และการคำนวณยังยืนขวางประตูอยู่เหมือนเดิม
สิ่งที่มันทำได้จริงคือ:

> **ค้นพบขอบเขตของตัวเอง แล้วสร้างวิธีการใหม่เพื่อขยายขอบเขตนั้น**

ต่างกันมหาศาล — อันแรกเป็นเส้นตรงที่พยายามเดินให้ไกลที่สุด อันหลังเป็น
ก้นหอยที่แต่ละรอบสร้างตัวเองเวอร์ชันใหม่

## 🌀 UI — ก้นหอยที่หมุนอยู่จริง

`ui/spiral.html` ไม่ใช่ภาพนิ่งของผลลัพธ์ แต่เป็น **เครื่องยนต์ทั้งตัวที่ถูกพอร์ตลง
JavaScript** — เปิดไฟล์ในเบราว์เซอร์แล้วก้นหอยหมุนต่อหน้าคุณ ไม่ต้องมีเซิร์ฟเวอร์
ไม่ต้องมีเครือข่าย กฎเหล็กสามข้อยังถูกบังคับอยู่ในโค้ดฝั่งเบราว์เซอร์เหมือนกันทุกข้อ

สองมุมมองของข้อมูลชุดเดียวกัน สลับด้วยปุ่มหรือปุ่ม `G` / `S`:

* **กราฟ** — กราฟความรู้แบบ force-directed สีของ node ไล่จาก "ยังไม่ติดไฟ" (UNKNOWN)
  ไปจนสว่าง (KNOWN) แดงคือขัดแย้ง และ **teal สงวนไว้ให้ node ที่ชื่อ `ระบบผู้ถามเอง`
  เท่านั้น** — สีนี้แปลว่าความสะท้อนกลับ ไม่ใช่ของตกแต่ง
* **ก้นหอย** — เกลียวกรวยที่ไต่ขึ้น: รัศมี = เวลา, ความสูง = ระดับคำถาม
  เห็นชัดว่าการถามค่อย ๆ ปีนจากระดับวัตถุขึ้นไปหาระดับที่ถามถึงตัวเอง

สิ่งที่ทำได้:

| | |
|---|---|
| คลิก node | แทรกคำถามเกี่ยวกับมันเข้าไปในก้นหอยทันที |
| พิมพ์ในช่องล่าง | แทรกคำถามของคุณเอง (เหมือน `spice ask`) |
| เลื่อน **เพดาน** | ตั้งเพดานจำนวน node — พอชนแล้วระบบจะบันทึกเป็น *ขอบเขตที่เพิ่งค้นพบ* แล้วขึ้นแบนเนอร์ให้คุณเป็นคนยกเพดาน นี่คือ "ระบบค้นพบขอบเขตของตัวเองแล้วขยายมัน" ในรูปแบบที่คุณมีส่วนร่วม |
| สามเหลี่ยม U/C/N | น้ำหนักการเลือกคำถามที่กำลังไต่เขาอยู่จริง พร้อมรอยทางที่มันเดินผ่าน |
| แผงประชากร | ยุทธวิธีเกิด/ตายสด ๆ ป้ายบอกที่มา: ต้นฉบับ · กลายพันธุ์ · ผสมข้าม · **จุดบอด** |

## ลองเลย

ไม่ต้องติดตั้งอะไรเพิ่ม แกนกลางใช้แค่ Python 3.10+ กับ stdlib

```bash
python3 demo.py                      # เดินก้นหอย 10 รอบให้ดู
python3 demo_wordless.py             # ก้นหอยกับโดเมนที่ไม่มีภาษาเลย
python3 -m unittest discover -s tests # 180 เทสต์

python3 -m spice run --topic "ก้นหอย" --epochs 20   # เก็บสถานะไว้เดินต่อได้
python3 -m spice ask "อะไรทำให้เราเรียกสิ่งนั้นว่ากลไก?" --level 4
python3 -m spice limits        # ขอบเขตของตัวเองที่ระบบตรวจพบ
python3 -m spice strategies    # ประชากรยุทธวิธีปัจจุบัน
python3 -m spice graph --dot g.dot && dot -Tsvg g.dot -o g.svg
```

หรือใน Python:

```python
from spice import Spiral

sp = Spiral.from_topic("ก้นหอย", seed=7)
sp.run(20)
print(sp.report())
```

## กฎเหล็กสามข้อ (บังคับในโค้ด ไม่ใช่แค่เขียนไว้เฉย ๆ)

### 1. ไม่มี `STOP = when answer found`

ระบบทั่วไป: `Question → Answer → DONE`
ก้นหอย: `Question → Answer → "คำตอบนี้อธิบายอะไรไม่ได้?" → Question'`

ทุก `Finding` ต้องมีฟิลด์ `residual` และเครื่องยนต์จะ **บังคับสร้างให้**
ถ้าตัวสืบค้นไม่คืนมา (`ensure_residual`) จากนั้น residual จะถูกทำให้เป็น
node สถานะ `UNKNOWN` ในกราฟทันที — คำตอบจึงกลายเป็น *เป้าหมายของคำถาม
รอบถัดไป* โดยอัตโนมัติ ไม่ใช่ปลายทาง

`tests/test_spiral.py::test_an_investigator_that_answers_completely_still_gets_a_residual`
พิสูจน์ว่าแม้เสียบตัวสืบค้นที่ตอบว่า "อธิบายได้ครบถ้วนสมบูรณ์" ทุกครั้ง
ก้นหอยก็ยังหมุนต่อ

### 2. ห้ามถามซ้ำ

ปัญหาที่เห็นได้ทันทีถ้าปล่อยให้ AI ถามว่า "มีคำถามอะไรอีกไหม?" คือได้
"แล้วทำไม? แล้วทำไม? แล้วทำไม?" ซึ่งเด็กสามขวบทำได้ฟรี ทางแก้ไม่ใช่
prompt ที่ฉลาดขึ้น แต่คือกลไกบังคับ:

| ชั้น | กลไก | ผล |
|---|---|---|
| 1 | signature ตรงกันเป๊ะ | ปฏิเสธทันที |
| 2 | **(ระดับ, หัววัด, เป้าหมาย) ซ้ำ** | ปฏิเสธทันที |
| 3 | ความใหม่ต่ำกว่าเกณฑ์ | ตกรอบการคัดเลือก |
| 4 | คล้ายคำถามที่เพิ่งเลือกใน epoch เดียวกัน (MMR) | ตัดทิ้ง |

ชั้นที่ 2 คือชั้นเชิง *แนวคิด* และแข็งแรงกว่าการเทียบตัวอักษรมาก: การกลายพันธุ์
ของแม่แบบผลิตคำถามที่ต่างแค่สำนวนได้ไม่จำกัด ระบบจึงหลอกตัวเองว่ากำลังสำรวจอยู่
ได้ตลอดกาล ถ้าเอาหัววัดชนิดเดิมไปจิ้ม node เดิมที่ระดับเดิมแล้ว ต่อให้เรียบเรียง
ใหม่หมดก็คือคำถามเดียวกัน

การวัดความคล้ายใช้ **character 4-gram** ไม่ใช่ word shingle — เพราะภาษาไทย
ไม่เว้นวรรคระหว่างคำ การตัดด้วย whitespace จะพังทันที

### 3. ตันแล้วให้ถามถึงความตัน — และหยุดเมื่อเครื่องมือหมดสภาพ

ถ้าคัดคำถามใหม่ไม่ครบโควตา ระบบจะสร้างคำถามระดับ `SELF_REFERENCE`
เกี่ยวกับความอิ่มตัวนั้นเอง:

> *"คำถามที่ระบบสร้างได้ทั้งหมดตอนนี้ถูกถามไปหมดแล้ว — คำถามชนิดใดที่
> **ภาษาปัจจุบันของระบบ** ยังพูดออกมาไม่ได้เลย?"*

ก้นหอยจึงไม่มีสถานะ "จบ" มีแต่สถานะ "ชนขอบเขต" — และการชนขอบเขตถูกบันทึกเป็น
*ขอบเขตที่เพิ่งค้นพบ* พร้อมคำถามต่อ ไม่ใช่ error

ขอบเขตมีสองชนิด: **เพดานทรัพยากร** (node / คำถาม / ต้นทุน) และ
**เครื่องมือหมดสภาพ** — เมื่อความประหลาดใจตกถึงพื้นต่อเนื่องสามรอบ ก้นหอยหยุด
แล้วพูดตรง ๆ ว่าคอขวดคือตัวสืบค้น ไม่ใช่วิธีถาม

การหยุดตรงนี้ไม่ขัดกฎข้อ 1 เพราะไม่ได้หยุดเพราะ "เจอคำตอบแล้ว" วัดได้ว่าถ้าไม่หยุด
มันเดินต่อได้อีกนาน แต่ผลผลิตกลายเป็นคำถามหนีความอิ่มตัวล้วน ๆ (อ้างถึงตัวเอง 68%
ใน 50 รอบท้าย) — ระบบพูดถึงการที่ตัวเองติดขัด แทนที่จะพูดถึงโลก

## หกระดับของคำถาม

ระดับไม่ได้เรียงตามความยาก แต่เรียงตาม **ระยะห่างจากวัตถุ** — ระดับ 0
ถามถึงโลก ระดับ 5 ถามถึงระบบที่กำลังถามอยู่

| # | ระดับ | ตัวอย่างที่ระบบผลิตเอง |
|---|---|---|
| 0 | วัตถุ | ก้นหอยเกิดขึ้นได้อย่างไร? |
| 1 | กลไก | กลไกอะไรที่ทำให้ก้นหอยเกิดขึ้น และกลไกนั้นต้องการเงื่อนไขอะไร? |
| 2 | ข้อสมมติ | เราสมมติอะไรไว้เงียบ ๆ ตอนที่พูดว่าก้นหอย? |
| 3 | อภิคำถาม | ทำไมคำตอบถึงออกมารูปนี้ และเกณฑ์อะไรทำให้เรานับว่ามันเป็นคำอธิบาย? |
| 4 | ภววิทยา | ก้นหอยมีอยู่จริง หรือเป็นหมวดหมู่ที่ผู้สังเกตสร้างขึ้นเพื่อความสะดวก? |
| 5 | อ้างถึงตัวเอง | ระบบนี้มีข้อจำกัด X — ข้อจำกัดนั้นทำให้มันมองไม่เห็นคำถามแบบไหน? |

ก้นหอยต้อง **ไต่ขึ้น ไม่ใช่เริ่มจากยอด** ระบบจึงเทียบสัดส่วนที่ใช้จริงกับ
*สัดส่วนที่ควรเป็น ณ วุฒิภาวะนั้น* (วัดจากขนาดกราฟ): ตอนกราฟยังเล็กน้ำหนักอยู่ที่
ระดับวัตถุกับกลไก แล้วค่อยแผ่ขึ้นเมื่อมีของรูปธรรมให้ถามถึงจริง

เดิมเทียบกับการกระจายแบบเท่ากันทุกระดับ ซึ่งพังตรงรอบ 0 พอดี — ยังไม่มีระดับไหน
ถูกใช้เลย ทุกระดับได้โบนัสเต็มเท่ากัน ก้นหอยเลยเริ่มที่ระดับภววิทยาทันที แล้วลาก
แนวคิดรูปธรรมอย่าง "ค่าแรงแฝงของเจ้าของร้านกาแฟ" ไปถามว่า *"ถ้าไม่มีใครมองอยู่
มันยังเป็นมันอยู่ไหม"* ซึ่งไร้ประโยชน์กับคนทำร้านกาแฟโดยสิ้นเชิง

```
หัวข้อใหม่ คำถามสามข้อแรกที่มันถาม:
  [วัตถุ] อะไรคือสิ่งที่เราสังเกตได้จริงเกี่ยวกับ X และอะไรที่เราแค่อนุมาน?
  [กลไก] กลไกอะไรที่ทำให้ X เกิดขึ้น และกลไกนั้นต้องการเงื่อนไขอะไรบ้าง?
  [กลไก] X เปลี่ยนแบบต่อเนื่อง หรือกระโดดเป็นขั้น?
```

## คำถามเลิกเป็นประโยค แล้วกลายเป็นโครงสร้าง

ข้อจำกัดที่ลึกที่สุดของเครื่องยนต์รุ่นก่อนคือ **คำถามเป็นสตริง** พื้นที่คำถาม
ทั้งหมดจึงถูกล้อมด้วยประโยคที่มนุษย์เขียนไว้ล่วงหน้า การกลายพันธุ์ทำได้แค่ระดับ
สำนวน — เปลี่ยนคำ ไม่เปลี่ยนรูปของการถาม

ตอนนี้คำถามคือ *ต้นไม้ของตัวดำเนินการ* (`spice/probe.py`):

```
BOUND(x)                      ขอบของ x อยู่ตรงไหน
REFLECT(BOUND(x))             เกณฑ์อะไรทำให้เรานับว่านั่นคือขอบ
LIMIT(REFLECT(BOUND(x)))      อะไรทำให้ผู้ถามตอบเกณฑ์นั้นไม่ได้
COMPARE(MECHANISM(a), MECHANISM(b))
```

ผลที่ตามมาสามอย่าง:

* **ระดับคำถามไม่ต้องประกาศอีกต่อไป** มันคำนวณจากรูปของต้นไม้ — ตัวยกระดับ
  แต่ละชั้นดันคำถามออกห่างจากวัตถุไปอีกขั้น คำถามที่ประกอบขึ้นใหม่จึงได้ระดับ
  ของมันเองโดยไม่มีใครกำหนดให้
* **ความซ้ำวัดที่โครงสร้าง** สองประโยคที่ต่างกันทุกคำแต่มีต้นไม้เดียวกัน คือ
  คำถามเดียวกัน — แข็งแรงกว่าการเทียบตัวอักษรมาก
* **ภาษาเป็นแค่ผิว** ต้นไม้ถามกับโดเมนที่ไม่มีคำศัพท์เลยก็ได้ การ render เป็น
  ภาษาไทยเป็นเรื่องของมนุษย์ที่มาอ่านทีหลัง ไม่ใช่เงื่อนไขของการถาม

การซ้อนใช้ **การแปลงเป็นวลีนาม** ไม่ใช่การยกทั้งประโยคมาใส่เครื่องหมายคำพูด —
เหมือนที่ภาษาจริงประกอบประโยคซ้อน มิฉะนั้นการซ้อนสามชั้นจะได้ประโยคที่ไม่มี
มนุษย์คนไหนอ่านจบ

## ไวยากรณ์ที่งอกหน่วยใหม่ขึ้นมาเอง

ตัวดำเนินการฐานมี 15 ตัว ถ้าหยุดแค่นั้น พื้นที่คำถามก็ยังถูกล้อมอยู่ดี แค่ล้อม
ด้วยตัวดำเนินการแทนที่จะล้อมด้วยประโยค

ภาษามนุษย์โตด้วยกลไกชื่อ **grammaticalization**: การประกอบที่ถูกใช้บ่อยและได้ผล
จะถูกยุบเป็นหน่วยเดียว แล้วหน่วยนั้นเอาไปประกอบต่อได้อีก โครงสร้างที่เคยต้องใช้
สามชั้นจึงพูดได้ในชั้นเดียว และความลึกที่ประหยัดไว้เอาไปสร้างรูปที่ก่อนหน้านี้
เอื้อมไม่ถึง `spice/grammar.py` ทำอย่างนั้น:

```
✦ รอบ 11: ไวยากรณ์หลอมหน่วยใหม่ «zata» = reflect∘bound

  รูปคำถามที่ใช้หน่วยนั้นต่อ:
    reflect(origin(zata(·)))
    limit(origin(zata(compare(·,·))))
    bridge(compare(zata(·),identify(·)),reflect(tension(·,·)))
```

ชื่อ `zata` ระบบตั้งเอง ไม่ได้ยืมจากภาษาใด และหน่วยที่งอกแล้วไม่ให้ผลจะถูก
ปลดระวาง — ไวยากรณ์ที่โตอย่างเดียวไม่ใช่ไวยากรณ์ที่เรียนรู้ มันคือไวยากรณ์ที่พอง

ผลิตรูปคำถาม 86 แบบ แต่**ไม่มีคู่ไหนถูกใช้ซ้ำพอจะตกผลึกเลยสักคู่** ภาษาจริงก็
ต้องการการใช้ซ้ำเช่นกัน — ความสำเร็จต้องพาไปสู่การทำซ้ำ การทำซ้ำจึงพาไปสู่การ
หลอมเป็นหน่วย การประกอบจึงเอนไปทางคู่ที่เคยได้ผล โดยคู่ที่ยังไม่เคยลองยังได้
น้ำหนักพื้นฐานไว้ การสำรวจจึงไม่ตาย

## โดเมนที่ไม่มีภาษาเลย

`spice/signal.py` ให้ลำดับสัญลักษณ์ดิบมาชุดหนึ่ง ไม่มีคำอธิบาย ไม่มีชื่อเรียก
ไม่มีแม่แบบประโยค **คำถามถูกประมวลผลเป็นการวัดจริง** และเศษที่เหลือคือ
*เซ็ตของตำแหน่งที่แบบจำลองทายผิด* — รูปที่บริสุทธิ์ที่สุดของ "คำตอบนี้อธิบาย
อะไรไม่ได้" ซึ่งกลายเป็นวัตถุชิ้นใหม่ให้ถามต่อได้ทันที

นี่คือคำตอบตรง ๆ ต่อข้อจำกัดที่ค้างมาตลอด: **ในโดเมนนี้ระบบรู้จริง เพราะมันวัดเอง**

```bash
python3 demo_wordless.py
```

ผลจากลำดับที่ซ่อนโครงสร้างไว้สี่ชั้น (ระบบไม่เคยเห็นตัวสร้าง):

| | ค่าที่ซ่อนไว้จริง | ที่ระบบวัดได้เอง |
|---|---|---|
| คาบพื้นฐาน | 7 | **7** (ทายถูก 84%) |
| จุดเปลี่ยนระบอบ | ตำแหน่ง 260 | **260** |
| จำนวนสัญลักษณ์ | 4 | **4** |

## ประดิษฐ์ตัวดำเนินการฐานขึ้นมาเอง

ไวยากรณ์ที่หลอมหน่วยได้ ยังตั้งอยู่บนตัวดำเนินการฐาน 15 ตัวที่มนุษย์เขียน และ
การวัดก็จำกัดอยู่ที่คาบ บล็อกซ้ำ เอนโทรปี สมมาตร — โครงสร้างชนิดอื่นมองไม่เห็นเลย

กุญแจคือ **การวัดคือโปรแกรม** (`spice/synth.py`) ตัวทำนายหนึ่งตัวคือฟังก์ชันคีย์
บวกตารางที่เรียนจากข้อมูลเอง และฟังก์ชันคีย์เป็นต้นไม้เล็ก ๆ ที่ประกอบได้:

```
i%7 · i÷k · ⌊i/k⌋%2 · prev1..3 · Δprev · runlen · (a × b)
```

"ตัวตรวจจับคาบ" กับ "ตัวตรวจจับมาร์คอฟ" กลายเป็นแค่สองจุดในปริภูมินี้ — และจุด
อื่นที่ไม่มีใครตั้งชื่อก็อยู่ในนั้นด้วย ระบบค้นหาด้วยเกณฑ์ MDL แล้ว **เลื่อนขั้น
โปรแกรมที่ชนะเครื่องมือเดิมซ้ำ ๆ ขึ้นเป็นตัวดำเนินการฐาน** พร้อมชื่อที่มันตั้งเอง
หลังจากนั้นไวยากรณ์เอาไปประกอบและหลอมต่อได้เหมือนตัวฐานทุกประการ

**การประดิษฐ์ถูกกระตุ้นด้วยความล้มเหลวของเครื่องมือเดิม** ไม่ใช่ด้วยการสุ่ม —
เมื่อตัวตรวจจับคาบทิ้งส่วนที่อธิบายไม่ได้ไว้มากเกินไป ระบบจะไปค้นหาเครื่องมือใหม่

| สัญญาณ | เครื่องมือเดิม | ที่ระบบประดิษฐ์ขึ้น |
|---|---|---|
| ซ้อนคาบ 7 กับ 13 | `i%7` ทายถูก 84% | **`(i%7×i%13)` ทายถูก 90.5%** — โครงสร้างที่ซ่อนไว้จริง |
| บริบท + สัญญาณรบกวน | `i%2` ทายถูก 69% | **`prev2` ทายถูก 95.8%** — โครงสร้างที่คาบมองไม่เห็นเลย |

แถวล่างคือประเด็น: ไม่มีการวัดชนิดไหนที่มีอยู่เดิมเห็นโครงสร้างแบบนั้นได้เลย

การจับคู่ใช้วิธี **มุ่งไปที่เศษ** — หาตัวที่อธิบาย *ตำแหน่งที่ตัวแรกทายผิด* ได้ดีที่สุด
แล้วค่อยจับคู่ ถ้าจับคู่แต่ตัวที่เก่งเดี่ยว ๆ จะพลาดโครงสร้างร่วมทั้งหมด (`i%13`
เดี่ยว ๆ คะแนนแย่มาก แต่พอคูณกับ `i%7` แล้วอธิบายสัญญาณได้เกือบหมด) — นั่นคือ
ตรรกะของก้นหอยเอง ใช้ซ้อนอยู่ข้างในการค้นหา

และเมื่อประดิษฐ์แล้ว มันถูกเอาไปประกอบต่อจริง:

```
reflect~extent( synth::kaphe( origin~reflect( bound(·) ) ) )
      ↑ หลอมเอง      ↑ ประดิษฐ์เอง    ↑ หลอมเอง
```

ตัวดำเนินการที่ประดิษฐ์ขึ้น ประกบด้วยหน่วยที่หลอมขึ้นเองสองตัว ในคำถามข้อเดียว

```bash
python3 demo_wordless.py --signal context   # โครงสร้างที่ตัวตรวจจับคาบมองไม่เห็น
```

## ความประหลาดใจ — สัญญาณที่ควรขับวิวัฒนาการ

เดิมยุทธวิธีได้เครดิตตาม "เพิ่ม node ได้กี่ตัว" ซึ่งเป็นตัวชี้วัดที่ตัวสืบค้น
ผลิตให้ฟรีอยู่แล้ว วิวัฒนาการจึงวิ่งเข้าหา *ปริมาณ* ไม่ใช่ *ความรู้*

คำถามที่ดีมีนิยามเดียวที่ตรวจสอบได้: **มันเปลี่ยนแบบจำลอง** ระบบจึงถ่ายภาพ
ย่านรอบเป้าหมายไว้ก่อนสืบค้น แล้ววัดสี่อย่างหลังจากนั้น (`spice/gain.py`):

| พจน์ | น้ำหนัก | วัดอะไร |
|---|---|---|
| `revision` | 0.34 | ความเชื่อ *ที่มีอยู่ก่อนแล้ว* ขยับไปเท่าไร |
| `freshness` | 0.26 | เศษที่ได้มาใหม่จริง หรือเป็นเศษเดิมที่วนกลับมา |
| `structure` | 0.22 | โครงสร้างใหม่ที่งอกในย่านนั้น |
| `conflict` | 0.18 | ความขัดแย้งที่ถูกเปิดโปงเพิ่ม |

`freshness` มีไว้แก้พฤติกรรมที่วัดได้จริง: ระบบเคยผลิตเศษเดิมซ้ำ ๆ
("โครงสร้างของก้นหอย" ซ้ำ 23 รอบ) SelfModel จับได้และบ่น แต่ fitness ไม่เคย
ลงโทษ ยุทธวิธีที่คายเศษเดิมจึงอยู่รอดสบาย ๆ

```
คำถามที่ให้ข้อมูลจริง : revision 1.00 · freshness 1.00 · total 0.68
คำถามที่คายเศษเดิม     : revision 0.00 · freshness 0.00 · total 0.00
```

ผลข้างเคียงที่สำคัญที่สุด: เมื่อความประหลาดใจตกต่ำต่อเนื่อง ระบบจะวินิจฉัย
**เครื่องมือของตัวเอง** เป็นข้อจำกัดชนิด `exhaustion` —
*"คำถามยังใหม่อยู่ แต่คำตอบไม่เปลี่ยนแบบจำลองอีกแล้ว คอขวดอยู่ที่ตัวสืบค้น
ไม่ใช่ที่วิธีถาม"* ซึ่งเป็นความจริง

## การเลือกคำถาม

```
Q* = argmax_Q ( w_u·U_Q + w_c·C_Q + w_n·N_Q )
```

| พจน์ | คือ | มาจาก |
|---|---|---|
| `U` | ความไม่รู้ในบริเวณเป้าหมาย | สถานะ node + เพื่อนบ้านรัศมี 1 |
| `C` | แรงดันจากความขัดแย้ง | เส้น `CONTRADICTS` ในบริเวณนั้น + ความสะท้อนกลับของระดับคำถาม |
| `N` | ความใหม่ | 1 − ความคล้ายสูงสุดกับคำถามเก่า × โบนัสระดับที่ยังไม่ถูกใช้ |

นอกจากสามพจน์นี้ยังมี **โบนัสสำรวจแบบ UCB1** บวกเข้าไป — ยุทธวิธีที่ยังถูกลองน้อย
ได้แต้มต่อ ไม่งั้นตัวที่บังเอิญได้คะแนนดีในสองรอบแรกจะผูกขาดการเลือกไปตลอด
(ซึ่งเป็นเหตุผลเดียวกับที่ SelfModel เคยฟ้องว่าเกิด monoculture) และคำถามที่
มนุษย์ถามเองจะขึ้นหัวแถวเสมอ ไม่ต้องแข่งกับคำถามที่เครื่องสร้าง

**`w` ไม่ใช่ค่าคงที่ที่มนุษย์ตั้ง** — มันถูกไต่เขาด้วย (1+1)-ES จาก
ผลตอบแทนจริงของแต่ละรอบ ระบบจึงเรียนรู้เองว่าตอนนี้ควรวิ่งไล่ความไม่รู้
ความขัดแย้ง หรือความแปลกใหม่ (มีเพดาน `[0.10, 0.60]` กันไม่ให้พจน์เดียว
กลืนฟังก์ชันเป้าหมาย ซึ่งก็คือการยุบก้นหอยกลับเป็นเส้นตรง)

ฟังก์ชันผลตอบแทนจงใจให้รางวัลกับการ **เปิด** ความไม่รู้ใหม่ ไม่ใช่แค่ปิดของเดิม
ระบบที่ถูกให้รางวัลกับความมั่นใจอย่างเดียวจะหยุดถามทันทีที่มันพอใจ

## มันแก้ไขตัวเองยังไง

ระบบนี้ **ไม่ได้เขียนซอร์สโค้ดตัวเองใหม่** (ไม่ปลอดภัยและไม่น่าเชื่อถือ)
แต่มันแก้สิ่งที่กำหนดพฤติกรรมของมันจริง ๆ ได้ทั้งหมด แล้วเซฟลงดิสก์ —
รอบถัดไปจึงโหลด "ตัวเองรุ่นใหม่" ขึ้นมาทำงาน ไม่ใช่รุ่นเดิม

| กลไก | ทำอะไร |
|---|---|
| **mutation** | เลื่อนระดับคำถาม สลับแหล่งเป้าหมาย แต่งแม่แบบใหม่ |
| **crossover** | ต่อคำถามสองแบบเข้าด้วยกัน ได้ลูกที่อยู่ *สูงกว่าพ่อแม่หนึ่งระดับเสมอ* เพราะการถามว่า "ถ้าถามสองอย่างนี้พร้อมกัน คำตอบจะเปลี่ยนไหม" คือการถามถึงตัวความสัมพันธ์ระหว่างคำถาม ไม่ใช่ถามถึงวัตถุอีกต่อไป |
| **capability gap** | เมื่อ `SelfModel` เจอจุดบอดที่ *อยู่ทน* ระบบจะให้กำเนิดยุทธวิธีใหม่ที่เล็งไปที่จุดบอดนั้นโดยตรง — "สร้างเครื่องมือใหม่เมื่อเครื่องมือเดิมไม่พอ" |
| **retirement** | ยุทธวิธีที่ไม่ให้ผลถูกปลดระวาง — แต่ห้ามทำให้ระดับคำถามใดหายไปทั้งระดับ (นั่นคือการสร้างจุดบอดด้วยมือตัวเอง) |
| **weight hill-climbing** | ปรับ `w_u, w_c, w_n` ตามผลตอบแทนจริง |

ตัวอย่างประชากรหลังเดินไป 14 รอบ (ทั้งหมดนี้ระบบสร้างเอง ไม่มีในโค้ดต้นฉบับ):

```
fitness  uses  gen  level            origin          name
  0.531     0    0  ข้อสมมติ         capability-gap  gap::ความขัดแย้ง 5 คู่ค้างอยู#841c02
  0.392     1    1  อ้างถึงตัวเอง    mutation        self_reference_probe~m1.832
  0.380     1    1  อ้างถึงตัวเอง    crossover       ontology_probe×object_probe@g1
  0.349     1    1  ข้อสมมติ         mutation        gap::แทบไม่เคยตั้งคำถามระดับข#a3c824~m1.752
```

## ขุดลึกก่อน แล้วค่อยอพยพ

ก้นหอยที่สุ่มทั่วกราฟอย่างสม่ำเสมอสำรวจได้กว้างแต่ตื้น — แตะทุกที่อย่างละนิด
ไม่ขุดที่ไหนจนถึงก้น ระบบจึงถือ **ย่านโฟกัส** หนึ่งย่าน (node + เพื่อนบ้านรัศมี 2)
ที่ได้น้ำหนักการสุ่มเพิ่ม แล้วอพยพเมื่อย่านนั้นตันจริง

การอพยพต้องผ่านเงื่อนไขครบทุกข้อ:

* ผ่านมาแล้วอย่างน้อย 8 รอบนับจากการอพยพครั้งก่อน **หรือ** ย่านนี้ให้คำถาม
  ไม่ครบโควตาติดกัน 3 รอบ (สัญญาณเฉพาะที่ ตรงกว่าความอิ่มตัวระดับทั้งระบบ)
* ย่านนี้ถูกเยี่ยมมาแล้วอย่างน้อย 4 ครั้ง
* SelfModel รายงาน `saturation` / `stagnation` / `exhaustion` ที่อยู่ทนอย่างน้อย 2 รอบ

ลองปล่อยให้อพยพได้ทุกรอบแล้ววัด: มันยิง **102 จาก 150 รอบ** — ก้นหอยไม่เคยอยู่
ที่ไหนนานพอจะขุดถึงก้น ผลแย่กว่าการสุ่มทั่วกราฟเสียอีก ใส่ความหน่วงแล้วเหลือ
~35 ครั้ง เป็นจังหวะที่ขุดจริงก่อนย้ายจริง

## เครื่องมือที่ระบบสั่งให้สร้าง

`comparative_probe` กับ `degree_probe` ไม่ได้มาจากการออกแบบล่วงหน้า — มันมาจาก
คำตอบของระบบเองต่อคำถามของตัวเอง เมื่อป้อนคำตอบจริงเข้าไปผ่าน `spice absorb`:

> **ถาม:** ข้อจำกัดนั้นทำให้มันมองไม่เห็นคำถามแบบไหน?
> **ตอบ:** มันมองไม่เห็นคำถามที่ถามว่า "อันไหนดีกว่า" — ระบบถาม อะไร/อย่างไร/
> ทำไม/ถ้าไม่ ได้หมด แต่ถาม "อันไหน" ไม่ได้ เพราะยุทธวิธีทุกตัวเล็งไปที่ node
> เดียวหรือคู่ที่ยังไม่เชื่อมกัน **ไม่มีตัวไหนเล็งไปที่ชุดที่ถูกจัดอันดับ**
> และมองไม่เห็นคำถามเชิงระดับขั้นด้วย เพราะทุกอย่างในกราฟเป็นหมวดหมู่ ไม่ใช่ปริมาณ

เป็นคำวินิจฉัยที่ถูก จึงเพิ่มแหล่งเป้าหมายชนิดที่เจ็ด — `comparison` คือคู่คำอธิบาย
ที่แข่งกันอธิบายสิ่งเดียวกัน (`KnowledgeGraph.rival_explanations`) — พร้อมหัววัดสองตัว
ที่ใช้มัน

## แบบจำลองที่ระบบมีต่อตัวเอง (`SelfModel`)

โมดูลนี้ไม่มองโลกเลย มันมองสถิติของก้นหอยเท่านั้น แล้วตรวจจับ:

| ชนิด | สัญญาณ |
|---|---|
| `coverage` | ระดับคำถามที่แทบไม่เคยถูกใช้ |
| `recurrence` | เศษที่ทนต่อการอธิบายมาหลายรอบ — **จุดบอดที่แท้จริง** |
| `stagnation` | ความไม่แน่นอนรวมไม่ขยับ / กราฟไม่โต |
| `saturation` | ความใหม่เฉลี่ยของคำถามกำลังยุบ |
| `unresolved` | ความขัดแย้งสะสมโดยไม่มีเกณฑ์ตัดสิน |
| `monoculture` | ยุทธวิธีเดียวผูกขาดคำถามเกินครึ่ง |
| `instrument` | เครื่องมือสืบค้นพัง |
| `exhaustion` | ความประหลาดใจตกต่ำ — **คอขวดคือตัวสืบค้น ไม่ใช่วิธีถาม** |
| `resource` | ใกล้ชนเพดาน node / คำถาม / ต้นทุน |

ข้อจำกัดพวกนี้ป้อนกลับสองทาง: เป็น **วัตถุดิบของคำถามระดับ 5** และเป็น
**ใบสั่งสร้างเครื่องมือใหม่** (ต้องรุนแรงพอ *และ* อยู่ทนอย่างน้อยสองรอบ
— ข้อจำกัดที่โผล่มารอบเดียวอาจเป็นสัญญาณรบกวน การรีบสร้างเครื่องมือตอบ
ทุกเสียงรบกวนคือวิธีที่ระบบจะพองจนไร้ทิศทาง)

ผลข้างเคียงที่สวยงาม: คำถามถึงตัวเองผูกกับ node ชื่อ `ระบบผู้ถามเอง`
เสมอ ระบบจึงสะสม **แบบจำลองของตัวเอง** ไว้ในกราฟความรู้เดียวกับที่ใช้
เก็บความรู้เรื่องโลก และถูกตั้งคำถามด้วยเครื่องมือชุดเดียวกัน

## ให้ใครก็ได้เป็นตัวสืบค้น (ไม่ต้องมีคีย์)

ปัญหาจริงของระบบนี้คือ *คำตอบกลวง* ไม่ใช่ *ไม่มีคีย์* — และคนที่ตอบได้ดีอาจเป็น
มนุษย์ที่รู้เรื่องนั้นจริง เซสชัน LLM ที่เปิดอยู่แล้ว หรือผลการทดลองจริงก็ได้

```bash
python3 -m spice propose --out questions.json   # ก้นหอยบอกว่ารอบนี้อยากรู้อะไร
#   (ใครก็ได้เติมช่อง answer ลงในไฟล์ — schema อยู่ในไฟล์นั้นเอง)
python3 -m spice absorb  --in  questions.json   # ก้นหอยรับคำตอบไปหมุนต่อ
```

ไฟล์พกบริบทไปครบ: เป้าหมายในกราฟ สถานะของมัน เศษที่ยังค้าง แนวคิดข้างเคียง
และกติกาที่ห้ามละเมิด (ข้อแรกคือ `residual` ต้องไม่ว่าง) คำถามที่ไม่มีใครตอบ
จะตกไปให้ตัวสืบค้นในตัว ก้นหอยจึงไม่หยุดหมุนเพราะมีคนตอบไม่ครบ

วัดผลจริงจากการที่ Claude ตอบคำถามของระบบเองสามข้อ:

| | ความประหลาดใจ | revision | freshness |
|---|---|---|---|
| ตัวสืบค้นออฟไลน์ | ~0.21 | 0.15 | 0.30 |
| **คำตอบจริง** | **0.70** | **1.00** | **0.98** |

## เสียบตัวสืบค้นจริง

`Investigator` เป็น Protocol ตัวเดียว ใครก็เสียบได้ — LLM, ฐานข้อมูล,
การทดลอง, เครื่องมือวัด

```python
class Investigator(Protocol):
    def investigate(self, q: Question, graph: KnowledgeGraph) -> Finding: ...
```

มีมาให้สองตัว:

* **`ReflectiveInvestigator`** (ค่าเริ่มต้น) — ออฟไลน์ ผลลัพธ์คงที่ตาม seed
  มันไม่ได้ *รู้* อะไรเกี่ยวกับโลก และไม่แกล้งทำเป็นรู้ มีไว้ทดสอบพลวัต
  ของก้นหอยโดยไม่ต้องมีเครือข่าย
* **`ClaudeInvestigator`** — เรียก Claude ผ่าน Messages API ด้วย
  structured outputs (`output_config.format`) โดย schema กำหนดให้
  `residual` เป็น required field ระบบจึงบังคับกฎข้อ 1 ได้ตั้งแต่ชั้น API

```bash
pip install anthropic
export ANTHROPIC_API_KEY=...          # หรือ `ant auth login`
python3 -m spice --backend claude run --topic "ก้นหอย" --epochs 10
python3 demo.py --claude
```

CLI ห่อไว้ด้วย `CompositeInvestigator(claude, reflective)` — ถ้า Claude
ล้มเหลว ก้นหอยไม่หยุด และ **ความล้มเหลวนั้นกลายเป็นข้อจำกัดที่ SelfModel
หยิบไปตั้งเป็นคำถามระดับ 5 ต่อเอง**

```
  gain.py          ความประหลาดใจ — revision / freshness / structure / conflict

  probe.py         พีชคณิตของการถาม — คำถามในฐานะต้นไม้ ไม่ใช่ประโยค
  grammar.py       ไวยากรณ์ที่หลอมหน่วยใหม่ของตัวเองขึ้นมา
  signal.py        โดเมนที่ไม่มีภาษา — คำถามถูกประมวลผลเป็นการวัดจริง
  synth.py         ปริภูมิของโปรแกรมการวัด + โรงหลอมตัวดำเนินการฐาน
  spiral.py        เครื่องยนต์ K→Q→E→A→C→M→Q'
  store.py         เก็บสถานะแบบ atomic เพื่อให้ "ตัวเองรุ่นใหม่" รอดข้ามการรัน
  cli.py           run / ask / propose / absorb / report / strategies / limits / graph
tests/             180 เทสต์ ไม่พึ่งเครือข่าย
```

## วัดผลจริงที่ 150 รอบ

ตัวเลขจาก `seed=42` ตัวสืบค้นออฟไลน์ (ทำซ้ำได้):

| | ep 0 | ep 50 | ep 100 | ep 149 |
|---|---|---|---|---|
| node | 7 | 126 | 270 | 297 |
| edge | 8 | 221 | 396 | 473 |
| ความขัดแย้งที่เปิดโปงได้ | 0 | 30 | 53 | 85 |
| ความใหม่เฉลี่ยของคำถาม | 1.00 | 0.40 | 0.37 | 0.38 |

* **คำถาม 450 ข้อ ไม่ซ้ำเลยสักข้อ** (กฎข้อ 2)
* **คำตอบที่ไม่มี residual: 0** (กฎข้อ 1)
* กระจายตามระดับ: อ้างถึงตัวเอง 41% · กลไก 17% · วัตถุ 15% · ภววิทยา 9% · อภิคำถาม 9% · ข้อสมมติ 8%
* ประชากรปลายทาง: capability-gap 11 · mutation 8 · crossover 1 · builtin 1

70 จาก 150 รอบเป็นรอบ "อิ่มตัว" — ระบบพูดตรง ๆ ว่าคำถามที่มัน *พูดออกมาได้*
หมดแล้ว แล้วหันไปถามถึงความอิ่มตัวนั้น นี่คือพฤติกรรมที่ออกแบบไว้ ไม่ใช่บั๊ก

> ตัวเลขข้างบนเป็นของเครื่องยนต์รุ่นแรก รุ่นปัจจุบันถามน้อยลงแต่คุ้มกว่า:
> 236–257 คำถาม แล้วหยุดเองที่รอบ ~117 เมื่อเครื่องมือหมดสภาพ (เดิมเดินยาว 450 คำถาม) เพราะการห้ามซ้ำเชิงแนวคิดตัดคำถามที่ต่างแค่
> สำนวนออกไป · สัดส่วนคำถามที่พับกลับหาตัวเองลดจาก 62% เหลือ **33%** ·
> ระดับกระจาย 12–26% ทุกระดับ ไม่มีระดับไหนครองเกินหนึ่งในสี่ · ทดสอบซ้ำหลาย seed
> และหลายหัวข้อได้ผลตรงกัน

### สามอย่างที่การทดสอบระยะยาวจับได้ (และถูกแก้แล้ว)

การรัน 10 รอบดูดีหมด ปัญหาจริงโผล่ตอนรัน 150 รอบ:

1. **generator มองแค่ 8 node บนสุดเสมอ** กราฟโตถึง 200 node แต่คำถามยังวนอยู่
   กับ 8 อันเดิม → ซ้ำ → ถูกกรอง → ระบบประกาศ "อิ่มตัว" ทั้งที่ยังไม่ได้มองอะไรเลย
   *แก้:* สุ่มถ่วงน้ำหนักจากสระ 48 อัน พื้นที่คำถามจึงโตตามกราฟ
2. **ยุทธวิธีที่ไม่เคยถูกใช้เลยปลดระวางไม่ได้** เพราะเงื่อนไขต้องมี `uses >= 3`
   ผลคือเครื่องมือจากจุดบอดสะสมจนกินประชากรไป 20 จาก 22 ตัว
   *แก้:* "ไม่เคยถูกเลือกเลยตลอด 8 รอบ" เป็นเหตุผลให้ปลดระวางพอ ๆ กับ "ถูกเลือกแล้วให้ผลแย่"
3. **ระบบโกงมาตรวัดของตัวเอง** คำถามหนีความอิ่มตัวมีเลขรอบอยู่ในตัว จึงใหม่ 100%
   เสมอ ระบบเลยรายงานว่าตัวเอง "สร้างสรรค์เต็มร้อย" ในรอบที่มันตันสนิท
   *แก้:* นับความใหม่เฉพาะคำถามที่ผ่านการคัดเลือกจริง ตัวเลขจึงลดจาก 1.00 ปลอม ๆ
   เหลือ ~0.38 จริง ๆ และ `SelfModel` ตรวจจับความอิ่มตัวได้ตามที่ควรเป็น

ผลรวม: รอบที่อิ่มตัวลดจาก 98 เหลือ 70, กราฟโตจาก 205 เป็น 297 node,
และสัดส่วนคำถามที่พับกลับมาหาตัวเองลดจาก 62% เหลือ 41%

## สิ่งที่ระบบนี้ **ไม่** ทำ

พูดตรง ๆ ดีกว่าปล่อยให้เข้าใจผิด:

* **มันไม่ได้เข้าถึงความจริงได้ไม่จำกัด** ความสามารถในการตั้งคำถามไม่ใช่
  สิ่งเดียวกับความสามารถในการรู้ ขอบเขตของคำตอบขึ้นกับตัวสืบค้นที่คุณเสียบเข้ามา
* **`ReflectiveInvestigator` ไม่รู้อะไรเกี่ยวกับโลกจริง** มันจำลอง
  *พลวัตของการสืบค้นที่ให้ผลไม่สมบูรณ์เสมอ* เพื่อให้ทดสอบก้นหอยได้ ถ้าต้องการ
  เนื้อหาจริงต้องใช้ `--backend claude` หรือเขียน investigator ของคุณเอง
* **การประดิษฐ์เกิดขึ้นภายในปริภูมิของคอมบิเนเตอร์ที่มนุษย์เขียน** มนุษย์เขียน
  คอมบิเนเตอร์ ระบบเขียนการวัด — เหมือนที่มนุษย์เขียนตัวดำเนินการ ระบบเขียนการประกอบ
  มันลึกลงไปอีกชั้นจริง และผลคือระบบเห็นโครงสร้างที่ไม่มีใครคาดไว้ล่วงหน้า
  แต่ไม่ใช่การสร้างจากความว่างเปล่า และคงไม่มีระบบไหนเป็นอย่างนั้นได้
* **ปริภูมิการวัดยังเป็นเรื่องของลำดับสัญลักษณ์** โครงสร้างต่อเนื่อง ภาพ กราฟ
  หรือความสัมพันธ์เชิงเหตุ ต้องการคอมบิเนเตอร์คนละชุด ซึ่งยังไม่มี
* **มันไม่เขียนโค้ดตัวเองใหม่** มันแก้ประชากรยุทธวิธี น้ำหนักการเลือก และ
  พื้นที่คำถามของตัวเอง — ซึ่งเป็นสิ่งที่กำหนดพฤติกรรมจริง แต่ไม่ใช่ซอร์สโค้ด
* **มันมีเพดานเสมอ** `Budget` มีไว้ให้ชน และการชนถูกออกแบบให้เป็น
  *ข้อมูล* ไม่ใช่ความล้มเหลว

สิ่งที่น่าสนใจที่สุดจึงไม่ใช่ AI ที่ตอบทุกคำถามได้ แต่เป็นระบบที่สร้าง
**พื้นที่ของคำถามใหม่ ๆ ที่ระบบรุ่นก่อนแม้แต่จะนิยามไม่ได้ว่าควรถามอะไร**
— ซึ่งคือสิ่งที่ crossover กับ capability-gap ในโฟลเดอร์นี้ทำอยู่จริง ๆ
