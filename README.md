# 🌶️ Spice

**เว็บแอปสั่งรันโมเดล AI ที่ยืมการ์ดจอ Tesla T4 จาก Google Colab มาเป็นแรงประมวลผล**

ล็อกอินด้วยบัญชี Google ครั้งเดียว → เปิด Colab วางคำสั่งบรรทัดเดียว →
การ์ดจอของ Colab กลายเป็นเครื่องประมวลผลของคุณ พร้อมเชื่อม Google Drive
ด้วย `rclone` แบบไม่ต้องตั้งค่าเอง

```
เบราว์เซอร์ ──สั่งงาน──▶ เซิร์ฟเวอร์ Spice ──จ่ายงาน──▶ Colab T4 ──▶ Google Drive
     ▲                      (คิว + โทเคน)                  │            (rclone)
     └──────────── ผลลัพธ์สดผ่าน SSE ───────────────────────┘
```

## 🚀 เริ่มใช้งานใน 5 นาที

### 1. ติดตั้งและรัน

```bash
git clone https://github.com/mataarranema-png/Spice.git
cd Spice
./run.sh                 # สร้าง venv ติดตั้งไลบรารี แล้วเปิดเซิร์ฟเวอร์ให้เอง
```

เปิด <http://localhost:8000> — ถ้ายังไม่ได้ตั้งค่า Google หน้าเว็บจะบอกให้ทราบ

### 2. ขอกุญแจ Google OAuth

1. เข้า [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials)
2. สร้างโปรเจกต์ (หรือเลือกโปรเจกต์เดิม) แล้วกด **Create credentials → OAuth client ID**
3. ถ้าถูกขอให้ตั้ง **OAuth consent screen** ก่อน: เลือก *External* → กรอกชื่อแอปกับอีเมล →
   ในหน้า *Scopes* ไม่ต้องเพิ่มอะไร → ในหน้า *Test users* **ใส่อีเมล Google ของคุณเอง**
4. กลับมาสร้าง OAuth client ID: เลือก **Web application**
5. ใน **Authorized redirect URIs** ใส่ให้ตรงเป๊ะ:
   ```
   http://localhost:8000/auth/google/callback
   ```
   (ถ้าใช้โดเมนจริง ให้ใส่ `https://โดเมนของคุณ/auth/google/callback` ด้วย)
6. ก๊อป **Client ID** กับ **Client secret** มาใส่ในไฟล์ `.env`

```bash
cp .env.example .env      # ถ้ายังไม่มี (run.sh สร้างให้อัตโนมัติ)
```

```ini
SPICE_SECRET_KEY=<ผลลัพธ์จาก: python3 -c "import secrets;print(secrets.token_urlsafe(48))">
GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxx
SPICE_BASE_URL=http://localhost:8000
SPICE_ALLOWED_EMAILS=อีเมลของคุณ@gmail.com     # แนะนำ: กันคนอื่นเข้าใช้เครื่องคุณ
```

รีสตาร์ตเซิร์ฟเวอร์ แล้วกด **เข้าสู่ระบบด้วย Google**

> 💡 **สำคัญ:** ตอนล็อกอิน Google จะขอสิทธิ์ Drive ด้วย — ต้องกด *อนุญาต*
> เพราะสิทธิ์นี้คือสิ่งที่ใช้สร้าง `rclone.conf` ให้อัตโนมัติ

### 3. ยืมการ์ดจอจาก Colab

1. ในเว็บ ไปที่ **เครื่อง GPU → + เชื่อมเครื่องใหม่** → จะได้รหัสจับคู่ 8 ตัว
2. เปิด [Google Colab](https://colab.research.google.com) → **Runtime → Change runtime type → T4 GPU**
3. ก๊อปคำสั่งบรรทัดเดียวจากหน้าเว็บไปวางในเซลล์ แล้วกดรัน
4. รอราว 10 วินาที เครื่องจะขึ้นสถานะ **ออนไลน์** ในหน้าเว็บเอง

หรือใช้โน้ตบุ๊กสำเร็จรูป: [`colab/Spice_GPU_Bridge.ipynb`](colab/Spice_GPU_Bridge.ipynb)
(อัปโหลดขึ้น Colab แล้วกรอกแค่ 2 ช่อง)

### 4. สั่งงานได้เลย

ไปที่ **สั่งงาน AI** → เลือกโมเดล → พิมพ์คำสั่ง → กดรัน

## 💻 ใช้คอมพิวเตอร์ของคุณเองเป็นเครื่องรัน

ไม่อยากพึ่ง Colab หรือมีการ์ดจอแรงอยู่แล้ว — ติดตั้งตัวแทนเครื่องลงคอมตัวเองได้เลย
ในหน้าเว็บกด **เครื่อง GPU → เชื่อมเครื่องใหม่** แล้วเลือกแท็บของระบบปฏิบัติการคุณ

**Windows** (เปิด PowerShell แล้ววาง)
```powershell
& ([scriptblock]::Create((irm https://เซิร์ฟเวอร์ของคุณ/install.ps1))) -Server https://เซิร์ฟเวอร์ของคุณ -Pair XXXX-XXXX
```

**macOS / Linux** (เปิด Terminal แล้ววาง)
```bash
curl -sSL https://เซิร์ฟเวอร์ของคุณ/install.sh | bash -s -- --server https://เซิร์ฟเวอร์ของคุณ --pair XXXX-XXXX
```

ตัวติดตั้งจะจัดการให้ครบ:

1. หา Python ในเครื่อง แล้วสร้างสภาพแวดล้อมแยกที่ `~/.spice/venv` (ไม่ไปยุ่งกับของเดิม)
2. ตรวจว่ามีอะไรให้ใช้ แล้วลง PyTorch ให้ตรงรุ่น — **NVIDIA (CUDA)**, **Apple Silicon (Metal/MPS)** หรือ CPU
3. จับคู่กับบัญชีคุณครั้งเดียว แล้วเก็บกุญแจไว้ที่ `~/.spice/config.json`
4. ถามว่าจะให้เปิดเองทุกครั้งที่เข้าเครื่องไหม (systemd / launchd / Task Scheduler)

**จับคู่ครั้งเดียวจบ** — ครั้งต่อไปสั่งแค่นี้ ไม่ต้องขอรหัสใหม่:

```bash
~/.spice/venv/bin/python ~/.spice/spice_agent.py
```

| อยากทำอะไร | คำสั่ง |
|---|---|
| ดูสถานะ (Linux) | `systemctl --user status spice-agent` |
| ดูบันทึก (Linux) | `journalctl --user -u spice-agent -f` |
| ดูบันทึก (macOS) | `tail -f ~/.spice/agent.log` |
| หยุดถาวร (Linux) | `systemctl --user disable --now spice-agent` |
| หยุดถาวร (Windows) | `Unregister-ScheduledTask -TaskName SpiceAgent -Confirm:$false` |
| จับคู่ใหม่ | เพิ่ม `--reset --server ... --pair ...` ตอนสั่งรัน |

> 🍎 **Apple Silicon** ใช้แรมร่วมกับ GPU ระบบจึงนับแรม 70% เป็น VRAM ที่ใช้ได้
> แต่ bitsandbytes (4bit/8bit) ใช้ได้เฉพาะ CUDA — บนแมคจะสลับไป fp16 ให้เอง

## 📦 ดึงโมเดลไหนก็ได้จาก Hugging Face

หน้า **คลังโมเดล** ค้นและเพิ่มโมเดลจาก Hugging Face ได้ทุกตัว ไม่จำกัดแค่ 6 ตัวที่มีมาให้
รวมถึงรุ่นที่ไม่มีการเซ็นเซอร์ (abliterated / uncensored / dolphin) ซึ่งมีชุดแนะนำให้กดเพิ่มได้ทันที

**สิ่งที่ระบบบอกให้ก่อนคุณจะเสียเวลาโหลดสิบกว่ากิกะไบต์:**

| เช็กให้ | ทำไมถึงสำคัญ |
|---|---|
| VRAM ที่ต้องใช้ ทั้ง fp16 / 8bit / 4bit | เทียบกับการ์ดที่คุณมีอยู่จริง แล้วขึ้น ✓ ให้อันที่ลงได้ |
| ขนาดพารามิเตอร์ | อ่านจาก metadata ก่อน ถ้าไม่มีค่อยเดาจากชื่อ — และรู้จัก MoE (`8x7B` = ~47B ไม่ใช่ 7B) |
| รูปแบบไฟล์ | GGUF / MLX / OpenVINO ใช้กับตัวแทนเครื่องนี้ไม่ได้ จะบอกเหตุผลตั้งแต่ก่อนกดเพิ่ม |
| ต้องขอสิทธิ์ไหม | รุ่นที่ต้องกดยอมรับเงื่อนไข (เช่น Llama ของ Meta) จะบอกให้ไปกดก่อน |

เพิ่มได้ทั้งจากช่องค้นหา หรือวางลิงก์ที่ก๊อปมาจากเบราว์เซอร์ตรง ๆ
โมเดลที่เพิ่มแล้วจะเข้าร่วมการเลือกอัตโนมัติด้วย ไม่ใช่ต้องเลือกเองเท่านั้น

**โทเคน Hugging Face** (ไม่บังคับ) — ใส่ในหน้าคลังโมเดลเมื่อจะใช้รุ่นที่ต้องขอสิทธิ์หรือ
รุ่นส่วนตัวของคุณเอง เก็บแบบเข้ารหัส และส่งให้เฉพาะเครื่องที่คุณจับคู่ไว้

> ⚠️ **เรื่อง `trust_remote_code`** — บางโมเดลต้องเปิดตัวเลือกนี้ถึงจะโหลดได้
> ค่าเริ่มต้นคือ **ปิด** เพราะการเปิดหมายถึงโค้ด Python จากผู้สร้างโมเดลจะถูกรันบนเครื่องที่
> เมานต์ Google Drive ของคุณอยู่ เปิดเฉพาะกับผู้สร้างที่คุณเชื่อถือจริง ๆ

## 🌐 ให้ Colab เข้าถึงเซิร์ฟเวอร์ของคุณ

Colab อยู่บนอินเทอร์เน็ต จึงเรียก `localhost` ของคุณไม่ได้ เลือกทางใดทางหนึ่ง:

**ก. Cloudflare Tunnel (ฟรี ไม่ต้องเปิดพอร์ต)**
```bash
cloudflared tunnel --url http://localhost:8000
# จะได้ URL แบบ https://xxx.trycloudflare.com → เอาไปใส่ SPICE_BASE_URL
# แล้วเพิ่ม https://xxx.trycloudflare.com/auth/google/callback ใน Google Console
```

**ข. ngrok**
```bash
ngrok http 8000
```

**ค. เซิร์ฟเวอร์จริง** — วางหลัง nginx/Caddy พร้อม HTTPS แล้วตั้ง
`SPICE_BASE_URL=https://โดเมนของคุณ` (คุกกี้จะเปลี่ยนเป็นโหมด `secure` ให้เอง)

> ⚠️ ทุกครั้งที่ URL เปลี่ยน ต้องอัปเดตทั้ง `SPICE_BASE_URL` และ
> **Authorized redirect URIs** ใน Google Console ให้ตรงกัน

## 🧠 ระบบอัจฉริยะทำงานอย่างไร

ทั้งหมดนี้เป็นตรรกะที่อ่านได้และเทสต์ได้ใน [`server/brain.py`](server/brain.py) และ
[`server/scheduler.py`](server/scheduler.py) — **ไม่ได้เรียกโมเดลภาษามาช่วยคิด**
จึงเร็ว ไม่มีค่าใช้จ่าย ไม่ต้องต่อเน็ต และให้ผลเหมือนเดิมทุกครั้ง

### 1. อ่านเจตนาจากคำสั่ง

| สิ่งที่ดู | ตัวอย่าง | ผลที่ได้ |
|---|---|---|
| ภาษา | “ช่วย refactor ฟังก์ชัน handleSubmit” | ไทย (ปนศัพท์อังกฤษก็ยังนับเป็นไทย) |
| ชนิดงาน | ไฟล์ `.m4a` ที่แนบมา | งานถอดเสียง (หลักฐานจากไฟล์ชนะคำในประโยค) |
| ความยาว | “สั้น ๆ” / “เขียนบทความ” | 256 หรือ 2048 โทเคน |
| ความแม่นยำ | งานโค้ด vs แต่งกลอน | temperature 0.2 vs 0.95 |

### 2. เลือกโมเดลให้พอดีกับเครื่องที่มีอยู่ *ตอนนั้น*

```
งานโค้ด + T4 16GB       → Qwen2.5 7B      (ต้องใช้การให้เหตุผลสูง)
งานสรุปภาษาไทย + T4     → Typhoon 2 3B    (ตอบไวกว่า พอสำหรับงานนี้)
งานโค้ด + การ์ด 6GB     → Typhoon 2 3B    + เตือนว่า "อยากใช้ Qwen แต่ VRAM ไม่พอ"
โมเดลที่โหลดค้างไว้แล้ว  → ถูกเลือกก่อน     (ไม่ต้องเสียเวลาโหลดใหม่)
```

### 3. วางเป็นลูกโซ่เมื่องานต้องทำหลายต่อ

> “ถอดเสียงไฟล์ประชุมแล้วสรุปเป็นข้อ ๆ”

```
ขั้น 1  Whisper large-v3-turbo  ถอดเสียงจาก gdrive:audio/meeting.m4a
   ↓    (ผลลัพธ์ไหลลงมาเอง)
ขั้น 2  Typhoon 2 3B            สรุปบทถอดเสียง → บันทึกกลับขึ้น Drive
```

ส่งครั้งเดียว ระบบสร้างงานขั้นถัดไปให้เองเมื่อขั้นก่อนหน้าเสร็จ
และถ้าขั้นไหนล้ม ลูกโซ่ที่เหลือจะหยุด ไม่เดินต่อด้วยข้อมูลที่ไม่มี

### 4. จัดสรรงานให้ตรงกับเครื่อง

เดิมเครื่องไหนขอก่อนก็หยิบงานบนสุดไป ซึ่งพังจริงสองแบบ — ตอนนี้แก้แล้วทั้งคู่:

- เครื่อง VRAM 6GB **จะไม่ถูกส่ง**งานที่ต้องใช้ 15GB (เดิมรับไปแล้วพังด้วย OOM)
- เครื่องที่โหลด Typhoon ค้างไว้ **จะได้งาน Typhoon ก่อน** แม้จะเข้าคิวทีหลัง

### 5. กู้คืนเองเมื่อหน่วยความจำไม่พอ

```
งานล้ม: CUDA out of memory (Qwen2.5 7B)
   ↓ ระบบตรวจเจอว่าเป็นปัญหาหน่วยความจำ
   ↓ ลดขนาดเป็น Typhoon 2 3B แล้วเข้าคิวใหม่ (ครั้งที่ 2)
   ↓ ฝั่ง Colab ล้าง VRAM ทิ้งให้ด้วย เพื่อไม่ให้พังซ้ำ
```

ลองให้อัตโนมัติครั้งเดียว ถ้ายังไม่ผ่านก็รายงานว่าล้มเหลวตามจริง
ส่วนงานที่ล้มด้วยสาเหตุอื่น (เช่นไฟล์ไม่มีอยู่) จะไม่ลองใหม่ให้ เพราะลองไปก็ได้ผลเดิม

### 6. ประเมินเวลาจากสถิติจริง

ETA คำนวณจากเวลาเฉลี่ยของโมเดลนั้นที่ *คุณเคยรันจริง* บวกเวลาโหลดโมเดลถ้ายังไม่อยู่ใน VRAM
บวกคิวที่รออยู่ข้างหน้า — ยิ่งใช้ไปเรื่อย ๆ ตัวเลขยิ่งแม่น

### 7. ดึงความรู้จากคลังมาตอบ (RAG)

เมื่อถามเป็นคำถามและในคลังมีเอกสารอยู่ ระบบจะค้นเอกสารที่เกี่ยวข้อง
แล้วแนบเป็นบริบทให้โมเดลโดยอัตโนมัติ พร้อมกำกับว่า “ถ้าข้อมูลไม่พอให้บอกตรง ๆ อย่าเดา”
(งานสร้างสรรค์อย่างการแต่งกลอนจะไม่ถูกยัดบริบทเข้าไป)

### 8. คุยต่อเนื่องและเห็นคำตอบไหลมาทีละตัว

หน้า **แชท** เก็บบทสนทนาเป็นเรื่อง ๆ โมเดลเห็นบริบทของรอบก่อนหน้าทั้งหมด
(ตัดของเก่าทิ้งเองเมื่อยาวเกินงบบริบท โดยรอบล่าสุดอยู่ครบเสมอ)
คำตอบถูกส่งกลับมาทีละท่อนระหว่างที่โมเดลกำลังพิมพ์ ไม่ต้องนั่งรอจนจบถึงจะเห็นอะไร

โหมดอัตโนมัติทำงานรายข้อความ — ถามเรื่องโค้ดได้ Qwen ถามเรื่องทั่วไปภาษาไทยได้ Typhoon
ในบทสนทนาเดียวกัน

### 9. ถามซ้ำ ไม่ต้องจุดการ์ดจอใหม่

```
ครั้งแรก : แปลประโยคนี้ → เข้าคิว → รันจริง → 6.5 วินาที
ครั้งที่สอง: แปลประโยคเดิม → ตอบทันที 0 วินาที (จากแคช)
```

แคชเฉพาะงานที่ *ควร* ได้ผลเหมือนเดิม คืออุณหภูมิ ≤ 0.35 เช่นแปลภาษา สรุปความ เขียนโค้ด
ส่วนงานสร้างสรรค์อย่างแต่งกลอนหรือคิดไอเดียจะไม่แคช เพราะคนถามซ้ำก็เพราะอยากได้คำตอบใหม่
งานที่อ่านไฟล์จาก Drive ก็ไม่แคช เพราะไฟล์อาจถูกแก้ไประหว่างนั้น

### 10. ด่านตรวจคุณภาพ — "เสร็จ" ไม่ได้แปลว่า "ใช้ได้"

โมเดลภาษาไม่ได้ล้มเหลวแบบโยน error เสมอไป สามอาการนี้ระบบเดิมนับว่าสำเร็จทั้งที่ใช้งานไม่ได้:

| อาการ | ตรวจเจอได้อย่างไร | ระบบแก้ให้อย่างไร |
|---|---|---|
| คำตอบว่าง | ไม่มีตัวอักษรที่ใช้ได้เลย | ดันอุณหภูมิขึ้นจาก 0 แล้วลองใหม่ |
| ถูกตัดกลางคัน | ใช้โควตาโทเคนหมดพอดี และไม่จบประโยค (หรือเปิดบล็อกโค้ดค้าง) | ขยายความยาวเป็นสองเท่า |
| วนพูดซ้ำ | ท้ายข้อความมีท่อนเดิมซ้ำติดกัน 4 รอบขึ้นไป | เพิ่ม repetition_penalty แล้วขยับอุณหภูมิ |

ซ่อมได้สูงสุด 2 รอบต่องาน ถ้ายังไม่ดีขึ้นก็ส่งผลตามจริง ไม่วนซ่อมไม่รู้จบ

### 11. งานชุด — สั่งทีเดียว วิ่งขนานทุกเครื่อง

```
คำสั่ง: "สรุปหัวข้อนี้เป็น 3 ข้อ: {{item}}"
รายการ: เศรษฐกิจไทย / พลังงานสะอาด / การศึกษา / ระบบขนส่ง
        ↓
แตกเป็น 4 งาน กระจายให้ทุกเครื่องที่ออนไลน์ช่วยกันทำ
        ↓
กดปุ่มเดียวคัดลอกผลทั้งชุดเป็น Markdown
```

ติ๊ก "แต่ละบรรทัดเป็นไฟล์ใน Drive" ได้ด้วย — จะกลายเป็นการประมวลผลไฟล์ทั้งโฟลเดอร์รวดเดียว
เวลาที่ประเมินจะหารตามจำนวนเครื่องที่ช่วยกันทำ ไม่ใช่บวกกันตรง ๆ

### 12. โหลดโมเดลรอไว้ตอนว่าง

ค่าโหลดโมเดลครั้งแรกคือส่วนที่นานที่สุดของงานแรกในแต่ละวัน
เมื่อเครื่องว่างและคิวโล่ง เซิร์ฟเวอร์จะบอกให้มันโหลดโมเดลที่คุณใช้บ่อยที่สุดใน 7 วัน
ที่ผ่านมารอไว้เลย — เอาเวลาว่างที่ยังไงก็เสียเปล่าไปแลกกับการที่งานจริงเริ่มได้ทันที
(ข้ามให้เองถ้ามีงานค้างอยู่ หรือโมเดลนั้นอยู่ใน VRAM แล้ว หรือเครื่องเล็กเกินจะรับไหว)

> 🔍 **ตรวจก่อนรันได้เสมอ** — ปุ่ม “ดูแผนก่อน” แสดงทุกอย่างที่ระบบตัดสินใจ
> พร้อมเหตุผลและคำเตือน ก่อนที่จะใช้ GPU ไปแม้แต่วินาทีเดียว

## 🗄️ rclone และ Google Drive ทำงานอย่างไร

Spice ไม่ได้ให้คุณรัน `rclone config` เอง แต่ใช้ refresh token ที่คุณอนุญาตไว้ตอนล็อกอิน
มาประกอบเป็นไฟล์ตั้งค่าให้ตรง ๆ:

```ini
[gdrive]
type = drive
client_id = <ของคุณ>
client_secret = <ของคุณ>
scope = drive
token = {"access_token":"…","refresh_token":"…","expiry":"…"}
```

- **หน้าเว็บ** — *Drive & rclone → ดาวน์โหลด rclone.conf* เอาไปใช้บนเครื่องไหนก็ได้
- **เครื่อง Colab** — ดึงไฟล์นี้เองผ่าน `GET /api/v1/worker/rclone` (ยืนยันตัวด้วย worker token)
  แล้วเมานต์ที่ `/content/gdrive` ให้อัตโนมัติ

เวลาสั่งงานจึงอ้างไฟล์ใน Drive ได้ตรง ๆ:

| ช่อง | ตัวอย่าง | ความหมาย |
|---|---|---|
| ไฟล์ต้นทาง | `gdrive:docs/รายงาน.txt` | อ่านไฟล์นี้เข้าไปเป็นบริบทให้โมเดล |
| โฟลเดอร์ปลายทาง | `gdrive:spice/outputs` | อัปโหลดผลลัพธ์กลับขึ้น Drive |

## 🔒 ความปลอดภัย

- โทเคน Google **เข้ารหัสด้วย Fernet** ก่อนเก็บ (กุญแจมาจาก `SPICE_SECRET_KEY`)
- worker token เก็บเป็น **SHA-256 hash** เท่านั้น ของจริงแสดงครั้งเดียวตอนจับคู่
- รหัสจับคู่ **ใช้ได้ครั้งเดียว อายุ 15 นาที**
- `state` ของ OAuth เซ็นด้วย HMAC พร้อมเวลาหมดอายุ — กัน CSRF
- คุกกี้เซสชันเป็น `httponly` + `samesite=lax` และเป็น `secure` เองเมื่อใช้ HTTPS
- ทุกคิวรีกรองด้วย `user_id` — ผู้ใช้คนหนึ่งมองไม่เห็นงาน เครื่อง หรือเอกสารของอีกคน
- ตั้ง `SPICE_ALLOWED_EMAILS` หรือ `SPICE_ALLOWED_DOMAINS` เพื่อปิดไม่ให้คนนอกล็อกอิน

> ⚠️ เครื่อง worker ที่จับคู่แล้ว **เข้าถึง Google Drive ของคุณได้** ผ่าน rclone
> ให้เชื่อมเฉพาะเครื่องที่คุณควบคุมเอง และกด “ถอดเครื่อง” เมื่อเลิกใช้

## ❓ คำถามที่พบบ่อย

**เครื่องขึ้นออฟไลน์ทั้งที่เซลล์ Colab ยังรันอยู่**
เซิร์ฟเวอร์เข้าถึงจากอินเทอร์เน็ตไม่ได้ หรือ Colab ตัดการเชื่อมต่อไปแล้ว —
ดูหัวข้อ *ให้ Colab เข้าถึงเซิร์ฟเวอร์ของคุณ*

**งานค้างที่ “รอคิว” ไม่ไปไหน**
ระบบจะบอกเหตุผลมาตรง ๆ ตอนส่งงาน เช่น “ไม่มีเครื่องที่รับงานนี้ไหว — gtx-1060:
ต้องใช้ VRAM 15000 MB แต่เครื่องนี้มี 6000 MB” วิธีแก้คือเชื่อมเครื่องที่ใหญ่พอ
หรือปล่อยให้โหมดอัตโนมัติเลือกโมเดลที่พอดีกับเครื่องที่มีให้เอง

**อยากคุมเองไม่อยากให้ระบบเลือก**
เปิดหัวข้อ “เลือกโมเดลเอง” ในหน้าสั่งงาน แล้วเลือกโมเดลกับพารามิเตอร์ตามต้องการ
ระบบจะทำตามที่สั่งเป๊ะ ๆ ไม่ตัดสินใจแทน

**Colab ตัดการเชื่อมต่อกลางคัน งานที่ค้างหายไหม**
ไม่หาย — งานที่ไม่มีความคืบหน้าเกิน 15 นาทีจะถูกโยนกลับเข้าคิวให้เครื่องอื่นทำต่อ

**ใช้การ์ดจอของเครื่องตัวเองแทน Colab ได้ไหม**
ได้ และมีตัวติดตั้งให้เลย — ดูหัวข้อ *ใช้คอมพิวเตอร์ของคุณเองเป็นเครื่องรัน* ด้านบน
รองรับทั้ง Windows, macOS (รวม Apple Silicon) และ Linux

**เชื่อม Colab กับคอมตัวเองพร้อมกันได้ไหม**
ได้ เชื่อมกี่เครื่องก็ได้ ระบบจะเลือกส่งงานไปเครื่องที่เหมาะที่สุดเอง —
งานหนักไปเครื่องที่ VRAM พอ งานที่ใช้โมเดลซึ่งโหลดค้างไว้แล้วก็ไปเครื่องนั้นก่อน

**โหลดโมเดลครั้งแรกนานมาก**
ต้องดาวน์โหลดน้ำหนักโมเดลก่อน (หลาย GB) รอบถัดไปจะเร็วขึ้นมากเพราะค้างอยู่ใน
หน่วยความจำของเครื่องแล้ว
