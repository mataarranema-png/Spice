# Myfxbook Earning System

ระบบติดตาม **รายได้จากพอร์ตเทรด** ที่ดึงข้อมูลจาก [Myfxbook](https://www.myfxbook.com)
รันในเครื่องตัวเอง ใช้ Python ล้วน ไม่ต้องติดตั้งไลบรารีเพิ่ม ไม่ต้องมีเซิร์ฟเวอร์

ระบบนี้ตอบคำถามที่กำไรในพอร์ตตอบไม่ได้: **ตกลงเดือนนี้เราได้ส่วนแบ่งเท่าไร จ่ายไปแล้วเท่าไร และยังค้างใคร**

---

## เปิดใช้งาน

| ระบบปฏิบัติการ | วิธีเปิด |
|---|---|
| Windows | ดับเบิลคลิก `START-WINDOWS.bat` |
| macOS | ดับเบิลคลิก `start-mac.command` |
| Linux | `./start-linux.sh` |
| ทุกระบบ | `python start.py` |

เปิดครั้งแรกจะสร้างฐานข้อมูลพร้อม **พอร์ตตัวอย่าง 3 พอร์ต** ให้ลองใช้ได้ทันทีโดยไม่ต้องต่ออินเทอร์เน็ต
เบราว์เซอร์จะเปิดหน้า `http://localhost:8820/` ให้เอง

ตัวเลือกอื่น

```
python start.py --port 9000    กำหนดพอร์ตเอง
python start.py --no-browser   ไม่ต้องเปิดเบราว์เซอร์
python start.py --sync         ซิงก์หนึ่งครั้งแล้วค่อยเปิด
python start.py --reset        ล้างข้อมูลแล้วสร้างตัวอย่างใหม่
```

ต้องใช้ Python 3.8 ขึ้นไป

## หัวใจของระบบ: ส่วนแบ่งแบบ High-Water Mark

ถ้าคิดส่วนแบ่งจากกำไรของทุกเดือนตรง ๆ จะเกิดปัญหาคลาสสิก คือ
พอร์ตขาดทุนหนักเดือนหนึ่ง แล้วเดือนถัดมาไต่กลับขึ้นมาที่เดิม
ผู้ลงทุนกลับต้องจ่ายส่วนแบ่งซ้ำสำหรับกำไรก้อนเดิมที่เคยจ่ายไปแล้ว

ระบบนี้จึงใช้ **High-Water Mark**: คิดส่วนแบ่งเฉพาะกำไรส่วนที่ทำ *จุดสูงสุดใหม่* เท่านั้น

ตัวอย่างจริงจากพอร์ตตัวอย่าง Gold Scalper A1

| รอบ | กำไรในรอบ | ฐานที่คิดได้ | HWM ก่อน → หลัง | รายได้ (40%) |
|---|---:|---:|---|---:|
| ก.พ. | +167.29 | 167.29 | 0 → 167.29 | 66.92 |
| มี.ค. | +492.42 | 492.42 | 167.29 → 659.71 | 196.97 |
| เม.ย. | −2,736.01 | 0 | 659.71 → 659.71 | 0 |
| พ.ค. | −955.34 | 0 | 659.71 → 659.71 | 0 |
| มิ.ย. | **+1,072.95** | **0** | 659.71 → 659.71 | **0** |

เดือนมิถุนายนทำกำไรได้พันกว่า แต่ยังไม่คิดส่วนแบ่ง เพราะกำไรสะสมยังไม่พ้นจุดสูงสุดเดิมที่ 659.71
ซึ่งเป็นพฤติกรรมที่ถูกต้องและยุติธรรมกับผู้ลงทุน

ปิดการใช้ HWM รายพอร์ตได้ ถ้าตกลงกับผู้ลงทุนไว้แบบอื่น

|---|---|

| **ภาพรวมรายได้** | เงินในพอร์ตรวม กำไรสะสม รายได้รอบนี้เทียบเป้า ยอดค้างจ่าย กราฟกำไรสะสมและกำไรรายวัน |
| **พอร์ตเทรด** | ตั้งเงื่อนไขส่วนแบ่งรายพอร์ต เลือกพอร์ตที่จะติดตาม ดู drawdown และกราฟย่อ 14 วัน |
| **รายละเอียดพอร์ต** | เส้นยอดเงิน กำไรรายวัน ตารางส่วนแบ่งรายรอบพร้อมคอลัมน์ HWM และประวัติการจ่าย |

| **การแจ้งเตือน** | drawdown เกินเพดาน ขาดทุนติดกัน 5 วัน พอร์ตที่ยังอยู่ใต้ HWM ข้อมูลเก่า และยอดค้างจ่าย |

## ศูนย์วิเคราะห์อัจฉริยะ

หน้านี้ใช้ข้อมูลที่มีอยู่แล้วตอบสามคำถามที่ตัวเลขสรุปธรรมดาตอบไม่ได้

### 1. สิ้นเดือนนี้จะได้เท่าไร

สุ่มซ้ำ (bootstrap) จากผลตอบแทนรายวันจริงของแต่ละพอร์ต จำลองอนาคต 2,000 เส้นทาง
แล้ววิ่งผ่านกติกา High-Water Mark เดิมทุกเส้นทาง ได้คำตอบเป็นช่วง ไม่ใช่ตัวเลขเดียวลอย ๆ

> ค่ากลาง 729 USD · ช่วงที่น่าจะเกิด 80% คือ 236 ถึง 1,299 USD · โอกาสถึงเป้า 71%

ใช้ bootstrap แทนการสมมติโค้งระฆัง เพราะผลตอบแทนการเทรดมีหางยาวกว่าโค้งระฆังเสมอ
และใช้ผลตอบแทนเป็นสัดส่วนไม่ใช่เม็ดเงิน เพราะพอร์ตที่โตขึ้นย่อมได้กำไรเป็นเงินมากขึ้นทั้งที่ฝีมือเท่าเดิม

### 2. จ่ายส่วนแบ่งตอนนี้ปลอดภัยหรือยัง

รายได้ของรอบคิดจากกำไร **ทั้งรอบ** ถ้าจ่ายกลางเดือนแล้วพอร์ตขาดทุนต่อ ยอดจริงตอนปิดรอบจะต่ำกว่าที่จ่ายไป
ระบบจึงบอกตรง ๆ ว่า

> มีโอกาส 33% ที่รายได้สิ้นรอบจะต่ำกว่ายอดที่คิดได้วันนี้ ถ้าจ่ายตอนนี้จะจ่ายเกินเฉลี่ย 237 USD

### 3. พอร์ตไหนกำลังจะระเบิด

พอร์ต martingale หรือ grid จะมีกราฟสวยมากจนถึงวันที่เสียเงินต้นทั้งก้อนในวันเดียว
ระบบตรวจสี่สัญญาณที่กลยุทธ์พวกนี้ทรยศตัวเอง

| สัญญาณ | ความหมาย |
|---|---|
| เพิ่มขนาดไม้หลังวันขาดทุน | หัวใจของ martingale วัดจากไม้เฉลี่ยหลังวันแพ้เทียบหลังวันชนะ |
| ชนะบ่อยแต่แพ้หนัก | ลายเซ็นของ grid ชนะเกิน 75% แต่วันแพ้ใหญ่กว่าวันชนะหลายเท่า |
| ความเสียหายกระจุกในวันเดียว | วันแย่ที่สุดหนักกว่าวันขาดทุนทั่วไปเกิน 8 เท่า |
| กราฟเรียบผิดธรรมชาติ | ความเสียหายส่วนหางใหญ่กว่าความผันผวนปกติมาก |

รวมเป็นคะแนนความเสี่ยงซ่อนเร้น 0-100 แล้วถ่วงเข้าคะแนนสุขภาพพอร์ตหนักที่สุด
เพราะนี่คือสิ่งที่ทำให้เสียเงินต้น ไม่ใช่แค่กำไรน้อย

### ตัววัดความเสี่ยงที่ใช้

Sharpe, Sortino, Calmar, ผลตอบแทนและความผันผวนต่อปี, ขาดทุนสะสมลึกสุด, จำนวนวันที่จมน้ำนานสุด,
VaR 95% ต่อวัน และ Expected Shortfall ทั้งหมดคำนวณจากผลตอบแทนรายวันจริงด้วยไลบรารีมาตรฐานล้วน

สำหรับพอร์ตที่จมอยู่ใต้ High-Water Mark ระบบจำลองต่อว่าโอกาสกลับมาสร้างรายได้ภายใน
30, 60, 90 วันทำการเป็นเท่าไร ซึ่งเป็นคำถามที่ต้องตอบลูกค้าได้

## การเชื่อมต่อกับ Myfxbook

ไปที่หน้า **เชื่อมต่อและตั้งค่า** → กด *เข้าสู่ระบบ Myfxbook* → ใส่อีเมลและรหัสผ่านของ Myfxbook → กด *ซิงก์ข้อมูล*

ระบบจะดึง

- พอร์ตทั้งหมดของบัญชี (`get-my-accounts`) และพอร์ตที่ติดตามอยู่ (`get-watched-accounts`)
- กำไรรายวันย้อนหลัง 1 ปี (`get-data-daily`) แล้วคิดส่วนแบ่งใหม่ทั้งเส้นเวลา

**เรื่องความปลอดภัย**

- รหัสผ่าน **ไม่ถูกบันทึกลงเครื่อง** ระบบส่งไปที่ Myfxbook เพื่อขอ session แล้วเก็บเฉพาะ session เท่านั้น
- ข้อมูลทั้งหมดอยู่ในไฟล์ `data/earning.db` ในเครื่อง ไม่มีการส่งออกไปที่อื่น
- เซิร์ฟเวอร์ผูกกับ `127.0.0.1` เท่านั้น เครื่องอื่นในวงแลนเปิดไม่ได้
- โฟลเดอร์ `data/` ถูกใส่ไว้ใน `.gitignore` แล้ว จะไม่ติดขึ้น git

ถ้ายังไม่พร้อมใช้ข้อมูลจริง กดปุ่ม *กลับไปโหมดสาธิต* ได้ตลอดเวลา ข้อมูลที่ซิงก์ไว้ไม่หาย

## พอร์ตหลายสกุลเงิน

พอร์ตแต่ละอันเก็บยอดด้วยสกุลเงินของตัวเอง (USD, THB, ...) ส่วนยอด **รวม** ทุกหน้าจะแปลงเป็น
สกุลกลางที่ตั้งไว้ก่อนบวกกัน แก้อัตราแลกเปลี่ยนได้เองที่หน้าตั้งค่า
อัตรานี้ใช้กับการแสดงผลเท่านั้น ไม่แตะข้อมูลการเทรดที่ดึงมา

## โครงสร้างโค้ด

```
app/database.py   โครงตาราง SQLite + ข้อมูลสาธิต + ตัวแปลงสกุลเงิน
app/myfxbook.py   ตัวเชื่อม Myfxbook API (urllib ล้วน) + ตัวแปลงข้อมูลที่ Myfxbook ส่งมา
app/earnings.py   เครื่องคิดส่วนแบ่ง High-Water Mark และการแบ่งรอบเวลา
app/analytics.py  พยากรณ์แบบ Monte Carlo ตัววัดความเสี่ยง และตัวจับพอร์ตซ่อนระเบิด
app/sync.py       เข้าสู่ระบบ ซิงก์ข้อมูลจริง และการต่อข้อมูลของโหมดสาธิต
app/api.py        ตรรกะของแต่ละหน้าจอ คืน JSON ให้หน้าเว็บ
app/server.py     เว็บเซิร์ฟเวอร์จากไลบรารีมาตรฐาน + ตารางเส้นทาง
web/              หน้าเว็บหน้าเดียว ไม่มี build step ไม่มีไลบรารีภายนอก กราฟวาดด้วย SVG เอง
```

ส่งออกเป็นซิปแจกจ่ายได้ด้วย `python ../build_zip.py Myfxbook-Earning-System`

## ข้อจำกัดที่ควรรู้

- ตัวเลขกำไรมาจาก Myfxbook ตามที่โบรกรายงาน ระบบไม่ได้ต่อกับ MT4/MT5 โดยตรง
- สมุดจ่ายเงินเป็นการ **บันทึกเอง** ไม่ได้ผูกกับการถอนเงินจริงของโบรกหรือธนาคาร
- รอบคิดส่วนแบ่งรองรับรายเดือนและรายสัปดาห์ เปลี่ยนรอบแล้วระบบจะคิดใหม่ทั้งหมดให้อัตโนมัติ
- การพยากรณ์ตั้งอยู่บนสมมติฐานว่าอนาคตหน้าตาเหมือนอดีต ซึ่งไม่จริงเสมอไป
  ถ้ากลยุทธ์เปลี่ยน ตลาดเปลี่ยน หรือเพิ่งเพิ่มความเสี่ยง ตัวเลขพยากรณ์จะตามไม่ทัน
  ให้ใช้เป็นเครื่องช่วยตัดสินใจ ไม่ใช่คำรับประกัน
- ตัวจับพอร์ตซ่อนระเบิดดูจากพฤติกรรมรายวัน ไม่ได้เห็นไม้รายตัว จึงบอกได้ว่า "น่าสงสัย" ไม่ใช่ "ยืนยัน"
- ต้องมีข้อมูลอย่างน้อย 20 วันทำการจึงจะวิเคราะห์ได้
